# Vouch — Third deep clean (18 November 2026)

## Release verdict

**NOT production-verified.** This package is an incremental source-hardening revision based on `vouch_storage_deep_sweep_2026-11-18.zip`, not a guarantee of bug-free runtime behavior. No deployment, production-data migration, or live payment-provider interaction was performed.

## Confirmed defects addressed

1. **Double signing / decline and duplicate audit:** public signing and decline handlers now serialize state changes with row locks in a database transaction. A repeated request cannot overwrite a final state or generate a second completion event. Sequential invitations use conditional `sent_at` updates to avoid duplicate invitations from concurrent callers.
2. **PDF/mail race:** a Laravel job chain processes signed PDF, audit trail, combined PDF, and completion notification in order. A failed generation step prevents a premature completion email. Other ancillary webhooks and search indexing remain dispatched separately.
3. **Live-template mutation:** new submissions snapshot the original template's `documents` array (`submissions.template_documents`), and signer pages, source-document downloads, PDF generation and admin previews use the snapshot. A nullable migration permits old rows to retain the previous fallback behavior; existing submissions are **not backfilled automatically**.
4. **Signer spoofing of fields:** the completion endpoint checks field ownership, does not allow a browser to overwrite a server-verified payment value, preserves earlier server-set values, and enforces unconditional required fields server-side. More complex conditional validation needs dedicated cross-channel tests.
5. **Concurrent signer uploads:** public and API attachment metadata updates use a row lock, and an upload is discarded if the signer has already closed the form before metadata persistence.
6. **Formula defect and arbitrary JavaScript execution:** template formulas previously used `{{Field Name}}`, but the signing component evaluated `{Field Name}` by invoking `Function(...)` on template-provided input. A typed restricted numeric evaluator now supports both placeholder syntaxes, arithmetic and parentheses, rejects other code, and has independent unit coverage. Advanced pre-existing JavaScript expressions will no longer run.
7. **Forged Stripe payment webhook:** the webhook now rejects missing secrets/signatures, verifies timestamp tolerance and HMAC, checks paid payment status, matches signer/workspace/field, checks the server-configured amount/currency, and uses an idempotent locked update. Stripe Checkout amount and return URLs are generated by the server from template payment settings instead of trusting the browser. The Stripe route explicitly bypasses browser CSRF because it validates provider HMAC instead. This is a **breaking API behavior change** for clients that supplied a `price_id`, `success_url` or `cancel_url`.
8. **SMS and email verification:** OTP guessing is limited; SMS now rejects unconfigured providers, rate limits requests, and does not report success on delivery failure. Public signing, decline and verification routes receive HTTP throttle limits.
9. **Unrelated-account attribution:** a user logged into a different workspace cannot be recorded as creator of a publicly started template submission.
10. **Frontend preview state:** signer values already stored by verified back-end flows are now provided to the signing React page on initial render.
11. **Build configuration:** removed the unused Tailwind v4 Vite plugin from the Tailwind v3-based project's declared dependencies. Source check and safe-formula tests are required by CI.

## Required steps before production deployment

1. Restore working network access, run `npm install` (not `npm ci` yet), and commit the regenerated `package-lock.json`; then run `npm ci`, `npm run check`, and fix **all** strict TypeScript errors without weakening compiler flags.
2. Install full Composer dependencies and required PHP extensions; run `composer validate --strict`, `vendor/bin/pint --test`, `php artisan test` (with a disposable test database) and full migration/rollback tests.
3. Test real sequential and parallel signing with two browsers, multiple concurrent clicks, signer attachment uploads, document changes after invitations, PDF assembly and webhook failures/retries.
4. Test Stripe's signed webhooks against a real **test-mode** integration; verify currency/minor units, retries, expiry, refunds and settlement. There is not yet a completed browser-based payment checkout integration in the signing React form.
5. Verify `tetranyble/storage` account scope and media metadata in the running package; build reference-aware media retention/garbage collection, document streaming, and operational reconciliation for failed queue chains.
6. For existing submissions, inspect and decide whether document manifests can be recovered from recorded template versions; do not retroactively assign the current template's documents without evidence.
